## Residual differences and questions

### V21-01 — stale manifest title (minor documentation correction)

`PHASE_MANIFEST.csv`, Pw02Preview row, still says “Story preview (25%)”. `canvas.json` correctly says “Issue preview (hook + first fact)”; the PDF and specification use hook/first fact. The precedence rule makes the intended behavior unambiguous. Correct the CSV title; no Phase 1 impact. The supplied manifest check compares phase prefixes, not full titles, so its pass does not disprove this observation.

### V21-02 — category example still suggests unconditional free access (Phase 2 copy)

Paywall2 p2 / Pw01HomeFree contains a “FACT CHECK — Free to read” badge for the road-tax example. The PD-10 proposal label is attached to a different flood-warning example. This does not prove an incorrect entitlement implementation: it may be a proposed individual free example. Label its conditional status or explain its approved eligibility before finalizing Phase 2 copy. The source check is satisfied by a PD-10 occurrence anywhere in that board.

### V21-03 — blanket GET rule conflicts with gift/referral writes (Phase 2 contract)

The API section says “GET requests never change state.” The gifted GET explicitly records a device open, and referral attribution says a consented `?r=` visit stores first-touch attribution. Clarify whether the intended rule is specifically “GET never spends a meter credit,” with explicit gift/referral exceptions, or whether admission/attribution must use POST. Consider link previews and prefetch behavior in that choice. This is a real wording conflict, not proof that a deployed endpoint mutates incorrectly.

### V21-04 — reopening an already consumed free issue needs a channel contract (Phase 2 engineering)

The meter promises cost-free reopening in the same week, but `metered` exists only on POST. GET's decision/cache table does not describe looking up existing meter_usage, and GET `/api/issues/{id}/full` lists account, gift or member rather than an admitted anonymous device. Define refresh, Back, shared deep links and subsequent full-JSON access for both guest and verified-account readers after consumption. Repeating POST at no extra charge may be intended; reference the chosen flow and tests rather than assuming a new grant architecture is necessary.

### V21-05 — the 10b mockup does not itself demonstrate scrolling (implementation requirement)

IssueReader.dc.html says longer cards scroll, but its reading `<main>` has `overflow:hidden` and placeholder text. Treat the 18px/scrolling rule in the engineering spec as normative and implement real overflow scrolling. The source min-height scan cannot prove reflow. The new code work tests actual long content at 320/360×640 and enlarged text instead of copying that placeholder behavior.

### V21-06 — proposed typography and Phase 2 dependencies remain open (declared decisions)

PD-07 is still pending. The provided source imports Google Fonts for its canvas; those requests must not be copied into production. Preview implementation can use system reading fonts and an outlined Newsreader wordmark while retaining current self-hosted font assets and the current budget. Final site-wide typography and OG/social font coordination require the font decision and measured release checks.

PD-01–PD-15 remain open as documented, including gateway, tax, legal/privacy, SMS provider, yearly/family rewards and optional product features. These are declared dependencies, not newly discovered defects. The missing “Use a free issue” design state is acknowledged by the owner and remains Phase 2 work.

Phase 1 preview work can continue, but production readiness cannot be asserted from this local build. Full details and remaining layout work are in `IMPLEMENTATION.md`.
